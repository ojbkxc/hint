# hint

> 面试实时提词器。本地语音识别，双通道区分「面试官」与「我」，多协议大模型流式作答。

hint 是一个 Windows 桌面小工具：它同时监听你的麦克风和系统播放的声音，把两路音频分别转成文字，判断面试官提出的问题，并把你事先准备好的简历与项目资料作为上下文，生成一段可以直接照着说的回答。

它只服务你本人：窗口可见、可随时关闭，不做进程伪装、不规避任何检测。关于「共享屏幕时对方看不看得到浮层」，见下方[屏幕捕获排除](#屏幕捕获排除默认关闭)一节——那里写清了它能做什么、**做不到**什么。

当前版本：**1.1.57**（仅 Windows 10/11 x64）。

## 功能概览

- Tauri 2 + React 19 + TypeScript，托盘、透明置顶浮层、全局热键
- **主题可切换（浅色默认 / 深色）**：语义化配色变量（参照 pi-agent-desktop 的主题做法）驱动，配置页与浮层共用一份设置。浅色 = 白底黑字（主窗口浅灰底 + 白卡片，与升级前观感一致），深色 = 黑底白字；改完点保存立即生效，浮层不用重开
- 设置页：三种 LLM 协议、简历与项目资料（支持从 TXT / MD / DOCX / PDF 导入）、回答风格、触发方式、音频设备、界面主题、浮层不透明度
- **Base URL 智能补全**：只填域名也行，自动补 `https://`、清理误贴的完整端点、按协议补版本段；粘贴 Anthropic / Gemini / 常见 OpenAI 兼容域名时自动切换协议
- **模型名从接口下拉**：点「刷新模型」从接口的 `/models` 拉取可用模型，下拉选择；也支持手动输入列表外的模型（兼容不支持 `/models` 的自建网关）
- API Key 只写入 Windows 凭据管理器（`keyring`），不落配置文件；**测试连接可直接使用尚未保存的 Key，测试成功后自动保存**，保存统一走底部「保存全部配置」
- 三协议流式 LLM（OpenAI 兼容 / Anthropic Messages / Gemini），支持取消、重新生成、失败重试
- 双通道采集：cpal 麦克风 + WASAPI loopback，16k 单声道重采样与双路电平上报
- **联合语音状态**：实时判断「面试官在说 / 你在说 / 双方同时」，浮层显示对应标识；迟滞边检测避免阈值抖动导致闪烁
- **软膝噪声门**：默认压低底噪（阈值 0.003），减少联合状态误判与 STT 噪声段；可在音频配置里关闭做 A/B 对比
- 本地 STT：sherpa-onnx 2.0.1 + SenseVoice Small INT8 + Silero VAD，模型按需下载（断点续传、sha256 校验）
- **断线恢复**：识别报错或卡住时自动中止并回收 worker 重试；恢复后用每路 120 秒环形缓冲补录遗漏片段（转录行标「补录」），补录始终让位于实时转录
- 问题判定、回声过滤、SQLite 会话留存、Markdown 导出与会话复盘页
- 连续多问：问题进入 FIFO 队列逐个回答，浮层显示「当前问题」与「排队 N」，排队数量实时更新
- 浮层不透明度可调（20%–100%，默认 88%）：整个浮层（含转录区与答案区）都跟随滑块透明，20% 时能清楚看到下方视频画面，文字始终可读
- **浮层字号可调（80%–300%，默认 100%）**：只缩放答案（含历史答案），转录与问题行保持固定大小，屏幕小或视力疲劳时可放大；保存后浮层立即生效，不用重开。基准字号为答案 17px、历史答案 15px（转录行 13.5px、问题行 12.5px），比 1.1.x 时代整体大一号
- **浮层默认尺寸按屏幕算**：首次显示时高度取屏幕可用高度的 1/3、宽度取可用宽度的 1/3（不小于 420、不超过 900 物理像素），水平居中、贴屏幕顶部；多显示器取主显示器，任务栏在顶部时贴的是扣掉任务栏后的上沿
- **记住浮层的位置、大小与显示状态**：拖过或改过尺寸就按原样恢复（防抖 800ms 写盘；恢复前与显示器工作区求交，换显示器后坐标落在屏外就回默认）。按 `Ctrl+Shift+H` 收起之后重启仍保持隐藏，不会自己弹回来
- **数据损坏不静默**：配置文件或会话数据库读不出来时，界面顶部弹出**不自动消失**的红条说明「已备份到哪、需要重新填写什么」；`hint --doctor` 也把这类问题列为阻塞项而不是显示成「没配过」
- **屏幕捕获排除（默认关闭）**：基于 Windows `WDA_EXCLUDEFROMCAPTURE`，开启后部分会议软件共享屏幕时不会捕获到浮层。**该机制有明显局限，默认关闭**，详见[屏幕捕获排除](#屏幕捕获排除默认关闭)
- **出网代理（直连 / 跟随系统 / 手动）**：装了 Clash / v2rayN 等代理软件的机器默认「跟随系统」，读 Windows「Internet 选项」里的设置；模型接口与模型下载共用同一份配置，本机回环永不代理
- 答案时间线：最新一轮答案在最上方，更早的问答按时间倒序排在下方，可滚动回看
- 日志落盘，设置页提供「打开日志目录」按钮
- **截图问答**：按 `Ctrl+Shift+S` 弹出全屏选区，拖动框住屏幕上的一段内容（题目、报错、代码片段），松开鼠标后把这一块屏幕交给当前模型流式作答，答案显示在浮层的独立区块；截图只在内存里编码、只发给你自己配置的接口，不落盘

## 快速开始

1. **安装**：运行 `hint_1.1.2_x64-setup.exe`，按向导完成安装（当前用户安装，无需管理员权限），启动 hint。
2. **配置模型接口**：打开主窗口的「设置」，在「模型接口」卡片选择协议（OpenAI 兼容 / Anthropic / Gemini），填写 Base URL（只填域名也行，失焦后自动补全）；模型名点「刷新模型」从接口拉取后下拉选择（也可手动输入），把 API Key 粘贴到 Key 输入框，直接点「测试连接」即可——测试会使用这个尚未保存的 Key，成功后自动保存到 Windows 凭据管理器。Key 的保存统一走底部「保存全部配置」按钮，卡片内不再单独放保存按钮。
3. **下载语音模型**：在「语音模型」卡片点「下载模型」，等待约 241 MB（241,357,257 字节）下载并校验完成，状态变为「已就绪」。
4. **选择音频设备**：在「设备」卡片选择麦克风与系统输出（或用「系统默认」），点「刷新设备」可重新枚举；修改设备后需要点「保存全部配置」。
5. **戴耳机**：建议佩戴耳机。外放时面试官的声音会被麦克风再次拾取，虽然程序会做回声过滤，但回声会降低识别准确率。
6. **开始面试**：在「面试会话」卡片点「开始面试」，或按 `Ctrl+Shift+R`。首次启动需加载本地语音模型，约 10–30 秒，状态先显示「正在启动…」，随后变为「面试进行中」。
7. **使用浮层**：开始面试后浮层会**自动显示**（已手动隐藏过则不强行弹出），结束面试后浮层**自动收起**。也可以按 `Ctrl+Shift+H` 显示 / 隐藏浮层。面试官提问后，答案会流式出现在浮层；浮层底部两路电平条持续跳动说明双通道都在工作。视频面试觉得浮层挡画面时，可在「回答行为」卡片调低「浮层不透明度」并保存。
8. **结束与导出**：点「结束面试」或再按 `Ctrl+Shift+R`。结束后切到「会话复盘」，选择本次会话，点「导出 Markdown」保存转录与问答记录。

## 热键与浮层

| 热键 | 作用 |
|---|---|
| `Ctrl+Shift+H` | 显示 / 隐藏浮层（**不是**开始/结束面试；开始面试时浮层会自动显示，结束面试时自动收起） |
| `Ctrl+Shift+R` | 开始 / 结束面试 |
| `Ctrl+Shift+A` | 对最新问题重新生成答案；会取消当前正在生成的答案，并优先回答最新问题 |
| `Ctrl+Shift+S` | 框选屏幕区域提问（选区截图 → 当前多模态模型流式作答，答案进浮层独立区块） |
| `Esc` | 隐藏浮层（浮层获得焦点时生效） |

`Ctrl+Shift+R` 是「切换」语义：启动过程中再按一次会排队停止（模型加载完立即结束），停止过程中再按一次会排队重新启动。快速连点不会产生并发启动或卡死状态。

浮层结构：

- 顶部：连接状态、首字延迟。
- 中部：双通道转录（「面试官」与「我」，回声行标注「回声」）。
- 答案区：当前问题 + 排队数量 + 最新一轮答案；向下滚动可看更早的问答时间线（最新在上，旧答案依次向下，最多保留最近 10 轮）。
- 截图问答区块：按 `Ctrl+Shift+S` 框选并得到答案后出现，独立于上面的语音问答时间线，不会被下一轮语音答案覆盖。
- 底部：麦克风 / 系统声电平条、当前模型名、首字延迟。

答案区按钮：「重新生成」对当前问题再要一次回答；「清空」只清空浮层显示，不影响已保存的会话记录。工具栏的「本场已答 N 题」是独立计数，不随时间线只保留 10 轮而停住。

正在流式生成时点「清空」：本轮剩余的增量和最终全文都不再上屏，答案区显示「本轮答案已清空，模型后续生成的内容不再显示」；否则下一帧增量会从半句处重新长出来、答案整段复活。要看完整答案重新点「重新生成」即可。

### 界面主题（浅色 / 深色）

设置页「回答行为 → 浮层外观」的第一项是「界面主题」，可选「浅色（白底黑字）」与「深色（黑底白字）」，默认**浅色**。

- 一份设置同时管两个窗口：配置页立刻换肤（选完就生效，不用等保存），浮层在点「保存全部配置」后收到主题事件、立即换肤，不用重开浮层。
- 实现是 CSS 变量：深色只是把 `:root` 的语义化配色变量换一组值（根元素挂 `data-theme="dark"`），版式、间距、字号完全一致，不会改一边漏一边。
- 浮层的深色是**黑底**而不是半透明白：底色 RGB 换成近黑，`--overlay-alpha` 仍控制整片不透明度——20% 时几乎全透、能看清视频画面，100% 时纯黑底；文字同步换成近白实色，光晕从白晕换成深色晕，压在深浅不一的画面上都能照着念。
- 原生控件（滚动条、输入框、下拉箭头）跟着主题走（`color-scheme`），深色页面里不会冒出亮色下拉箭头。

### 浮层尺寸、位置与显示状态

**首次启动**（配置里还没有记录）按主显示器算尺寸与位置：

- 高度 = 屏幕**可用区域**高度的 1/3；
- 宽度 = 可用区域宽度的 1/3，且不小于 420、不超过 900 物理像素；
- 水平居中、垂直贴顶（贴着可用区域上沿，不再额外留边距）。

「可用区域」是扣掉任务栏之后的区域，所以任务栏放在顶部或侧边时浮层不会被压住。

**之后启动会沿用你调过的位置和大小**：拖过浮层或改过尺寸，配置里记下几何（物理像素，
与 Win32 `GetWindowRect` 同一套口径），下次启动照原样恢复。恢复前会与当前显示器工作区
求交——换过显示器、拔掉副屏、改过分辨率之后，上次的坐标可能整个落在屏幕外（那时既看
不见也拖不回来），交集不足 1/3 就回到默认几何。

拖动结束 800ms 后才写盘（拖动时 `Moved`/`Resized` 每帧都触发，直接写会疯狂 IO）。

**浮层显示状态也会记住**：按 `Ctrl+Shift+H` 或点浮层右上角收起之后，重启仍保持隐藏，
不会自己弹回屏幕上。首次启动默认显示（否则你不知道它存在）。

> 单位踩过的坑：`WebviewWindow::inner_size()` / `outer_position()` 的返回类型写着
> `PhysicalSize` / `PhysicalPosition`，实测在这台机器上给的是「物理 × dpr」（Win32 物理
> 宽 750、dpr 1.25 时返回 938），而 `set_size` 又除回去。读写带同一偏差看起来自洽，换台
> DPI 不同的机器就摆歪。现在存取都直接用 Win32 `GetWindowRect` / `SetWindowPos`。

设置页「回答行为」卡片里有「浮层不透明度」滑块，范围 20%–100%，默认 88%，按 1% 步进调整。

- 滑块值直接等于**整个浮层**的白色背景不透明度：调到 20% 时只剩两成底色，能清楚看到下方的视频画面；调到 100% 时完全不透明。
- 转录区、答案区、头尾栏不再单独铺不透明衬底，滑块在整个浮层面积上都肉眼可见。
- 浮层不使用整窗透明，文字本身始终不透明；浅色主题下正文是深色字 + 白色光晕阴影，深色主题下换成近白字 + 深色光晕，压在亮或暗的视频画面上都能照着念。
- 点「保存全部配置」后立即生效，无需重启或重新显示浮层。
- 该设置只影响外观，**不改变窗口是否可见**，也不影响屏幕共享中的可见性。要影响捕获行为请用「屏幕捕获排除」开关（默认关闭，局限见下）。

### 截图问答（`Ctrl+Shift+S`）

面试里有一部分内容不是「说」出来的：屏幕上共享过来的一段代码、一个报错、一道在线笔试题。`Ctrl+Shift+S` 让你把这一小块屏幕直接变成提问的上下文。

1. 按 `Ctrl+Shift+S`，屏幕上铺一层全屏选区，光标变成十字。
2. 按住左键拖出要问的区域，拖动过程中实时显示 `宽 × 高`；松开鼠标即在那一刻完成抓取。按 `Esc` 取消，什么都不发。
3. 选区太小（不足 8×8 像素）时只提示「选区太小，请重新拖拽」，不抓取、不发送。
4. 抓到的截图会随一个提问一起发给你**自己在设置页配置的模型接口**，流式生成的答案显示在浮层新增的「截图问答」区块里，与语音问答的答案时间线分开显示，互不覆盖。

限制：

- **必须用支持视觉输入的模型**。模型不接受图片（很多纯文本模型如此）时，接口会直接返回错误，浮层会给出错误提示；去「模型接口」卡片换一个支持图片的多模态模型即可，协议、Base URL 与 Key 仍是同一份配置。
- 单次选区上限 4096×4096 像素；框得过大时会提示缩小选区再拖一次。
- 截图问答与语音问答共用同一套协议 / Base URL / Key 配置，不用单独再配一遍。

隐私边界（截图只在内存里待着）：

- 截图只在内存里编码成 JPEG 后再随请求发出去，**不写磁盘**、不进会话数据库、日志里也不含任何图像数据（最多只有「选中了多大区域」这类尺寸信息）。
- 只发给你**自己在本机填的模型接口**，不经过任何中转，也不发往第三方。
- **不做后台持续截屏、不做全屏轮询**：只有你按下 `Ctrl+Shift+S` 并且真的框选了一块区域，程序才会抓取那一次。

### 资料导入（简历 / 项目资料）

简历与项目资料两个输入框右上角都有「从文件导入」按钮，支持：

- **TXT / MD**：自动识别 UTF-8（含 BOM）、UTF-16（带 BOM，记事本「Unicode」）与 GBK 编码；
- **DOCX**：本地解析 `word/document.xml`，保留段落结构；解压后的 XML 上限 32 MB，超大文件会提示「DOCX 内容过大…请在 Word 中另存为 TXT 后再导入」；
- **PDF**：本地提取文本层；扫描版 PDF 没有文本层，会提示改用 DOCX 或 TXT（OCR 不在本版范围）。

导入在本机离线完成，文件不会上传；单文件上限 20 MB，导入后按 6000 字截断并提示（与提示词注入上限一致；超出 20 万字符的文本会在命令层先行截断）。旧版 `.doc` 不支持，请在 Word 里另存为 `.docx` 或 `.txt`。

### Base URL 智能补全

Base URL 输入框失焦时自动规范化，常见写法都能直接工作：

| 你填的 | 实际使用（OpenAI 兼容协议） |
|---|---|
| `api.deepseek.com` | `https://api.deepseek.com/v1/chat/completions` |
| `https://api.deepseek.com` | `https://api.deepseek.com/v1/chat/completions` |
| `https://api.deepseek.com/v1` | `https://api.deepseek.com/v1/chat/completions` |
| `https://x.com/v1/chat/completions`（完整端点） | 原样使用，不会拼成 `…/chat/completions/chat/completions` |
| `https://gateway.local/v2` | `https://gateway.local/v2/chat/completions` |

- Anthropic 填 `https://api.anthropic.com`（带 `/v1` 或完整 `/v1/messages` 均可），Gemini 填 `https://generativelanguage.googleapis.com`（带 `/v1beta` 均可），版本段由后端自动去重。
- 粘贴 `anthropic.com`、`generativelanguage.googleapis.com`、`api.openai.com`、`api.deepseek.com`、`dashscope.aliyuncs.com`、本地 `localhost` 等可识别域名时，协议会自动切换。
- 识别不出来（例如自建网关）时保持你当前选择的协议，不做猜测。

### 连续多个问题

面试是持续进行的，连续出现多个问题时：

- 新问题不会打断正在生成的答案；问题进入 FIFO 队列，按顺序逐个回答。
- 浮层显示「当前问题」和「排队 N」，`N` 随作答递减；排队数量实时更新，流式过程中新问题入队也会立即反映。
- 每轮作答开始时会取最新对话历史（包含上一轮已生成的答案），答案也会写入历史供后续问题引用。
- 待答队列最多 5 个（此外还有 1 个正在作答）。超出时忽略最新一条，并提示「问题积压较多，已忽略最新一条；可按 Ctrl+Shift+A 优先作答当前问题」。
- 停止会话会清空队列与新会话历史。
- 同一句话被 STT 重复识别时只会回答一次：去重只忽略标点、空白与礼貌用语（如「请」「麻烦」「呢」「吗」）的差异；**内容不同的追问一律排队回答，不会被合并**。
- 只有 `Ctrl+Shift+A`（或浮层「重新生成」）会打断当前答案：取消当前生成、清空排队，优先回答最新问题。

### 回答行为

回答提示词遵循这些硬约束：不暴露 AI 身份或提词器；按提问顺序回答多个问题；只使用简历与项目资料中的事实，资料未覆盖时说明边界、不编造；跟随面试官提问的语言；追问时补充新信息、不重复上一轮内容。口语短答默认 150 字以内，问题要求介绍项目 / 经历 / 流程时可放宽到 250 字；要点提纲风格输出 5–7 条编号要点，每条不超过 40 字。

## AI 接口失败怎么办

这是面试现场最高频的故障，处理方式按错误类型区分。

失败时，浮层答案区会出现一条红色错误条，并以中文说明原因；**已经生成的部分内容会保留**，不会丢失。

- **可重试类**（网络中断、超时、限流 429、服务端 5xx、流式连接中断）：错误条右侧显示「重试」按钮，点击即重新生成；也可以按 `Ctrl+Shift+A`。
- **不可重试类**（401 Key 无效或未保存、403 无权限 / 额度不足、404 Base URL 或模型名错误）：错误条**不显示**「重试」按钮，重试无用，必须去设置页修配置：
  - 401：到「模型接口」卡片重新粘贴对应协议的 API Key，点「保存全部配置」。
  - 403：检查账号状态、套餐或额度。
  - 404：核对 Base URL 与模型名。Anthropic / Gemini 的 Base URL 带不带 `/v1`、`/v1beta` 都能用；OpenAI 兼容协议填到 `/v1` 这一级。
- **首字前失败**：后端会自动重试一次（间隔约 1.5 秒），用户感知为「稍微慢一点」；仍然失败才显示错误条。
- **流到一半断开**：不会自动重试（避免内容重复），错误条会提示「生成中断（已保留已生成内容，…）」，需要手动重试。
- **接口返回空响应**（一个字都没收到却「成功」，最常见是网关忽略 `stream: true` 直接回整包 JSON、或模型名不是对话模型、内容被过滤）：错误条提示「模型接口没有返回任何文本（流式响应为空）…」，不再让答案区停在空白上；确认 Base URL 与模型名后重试。
- **会话状态不受影响**：一次生成失败不会结束会话，状态仍是「面试进行中」，可以继续提新问题，不必重新开始面试。
- **排查日志**：设置页底部的「打开日志目录」会打开 `%APPDATA%\com.ojbkxc.hint\logs`，日志文件为 `hint.log`（超过 5 MB 轮转为 `hint.1.log`）。反馈问题时请附上 `hint.log`。

## 常见问题

**配置文件损坏了怎么办？简历和项目资料都没了**

界面顶部会弹出一条**不会自动消失**的红条：

> 配置文件损坏，已回退默认设置；原文件已备份为「settings.json.bad」。简历与项目资料需要重新填写。

意思是 `%APPDATA%\com.ojbkxc.hint\settings.json` 读不出来（写入中断、磁盘故障、手工编辑出错），
程序已经：

1. 把坏文件改名成 `settings.json.bad` 留在原目录（**没有删**，可以拿去手工抢救）；
2. 回退到默认设置继续启动，不至于打不开。

**需要重新填写简历与项目资料**。`hint --doctor` 也会把这条列为阻塞项，而不是像以前那样
只显示「配置文件不存在，使用默认值」——那看起来像从没配过。

> 这条提示为什么不自动消失：它要告诉你的是一件事（你的数据被重置了、要去重填），
> 10 秒后自己消失等于没提示。

**会话历史记录突然全空了**

界面顶部会出现另一条红条（同样不自动消失）：

> 会话数据库打不开，已临时改用内存记录：历史面试记录无法读取，本次关闭后新记录也会清空。
> 请检查磁盘空间或权限后重启。

`%APPDATA%\com.ojbkxc.hint\hint.db` 打不开时，程序会退到内存库保证还能启动，但**内存库只在
本次运行有效**：历史记录读不出来，本次新产生的记录在退出后也会消失。

先按下暂停键：检查磁盘剩余空间与目录权限，然后重启。数据库文件本身没有删除，问题排掉后
重启即可读回；`--doctor` 会报「数据库完整性检查未通过 / 会话数据库无法打开」。

**开始面试提示「未配置 OPENAI 的 API Key，请先在设置页保存后再开始会话。」**

说明当前协议还没有保存 Key。到「模型接口」卡片粘贴对应协议的 Key（OpenAI / Anthropic / Gemini 的 Key 互不通用），点「保存全部配置」，再点「测试连接」确认。

**点「测试连接」提示「当前接口还没有保存 API Key」。**

说明 Key 输入框是空的、凭据管理器里也没有该协议的 Key。把 Key 粘贴进输入框后**直接点「测试连接」**即可：测试会使用未保存的 Key，成功后自动写入 Windows 凭据管理器；也可以点底部「保存全部配置」一并保存。OpenAI / Anthropic / Gemini 的 Key 互不通用，切换协议后需要各自保存一次。

**语音模型下载中断了怎么办？**

已下载的部分会保留在 `.part` 文件里。恢复网络后回到「语音模型」卡片，点「下载模型」即可从断点续传；卡片会显示「已有 X MB，支持断点续传」。网络中断的提示是「网络连接中断。已下载部分会保留，恢复网络后继续。」。下载前需要至少约 300 MB 可用空间，磁盘不足会提示「磁盘空间不足：当前可用约 X MB，本次还需要约 Y MB」（续传时 Y 会小于首次安装）。若提示「文件校验失败，已删除损坏部分。请重新下载。」，重新点下载即可。

**卸载重装后为什么又让我下载语音模型？（已修复）**

1.0.26 及更早版本模型存在 `%APPDATA%\com.ojbkxc.hint\voice`，卸载器勾选「删除应用数据」时会连它一起删。1.0.26 起模型存放在 `%LOCALAPPDATA%\hint-models`（不含应用标识），卸载器不会触碰；旧位置已下载的模型在启动时自动搬移过去。若从 1.0.26 或更早版本升级，第一次启动后到设置页确认状态为「已就绪」即可。

**面试中插拔耳机 / 切换了系统默认播放设备，会不会丢系统声？**

不会。输出设备选择「系统默认」时，程序自己迁移采集端点到新设备，浮层只出现一条「警告：系统默认输出设备已变更，正在切换到新的输出设备继续采集」。设备切换属正常路径，不计入通道失败——连插拔几次耳机也不会把系统声通道判死（旧版每次切换都算一次失败，15 秒内超过 5 次就再听不到面试官）。

若设置页显式指定了某个输出设备，程序不会替你改设备，只提示一次「警告：系统默认输出设备已变更，当前会话仍在采集旧设备…」，按提示结束会话、重新选设备再开始。

**浮层底部只有一路电平在动。**

说明只有一个音频通道启动成功，浮层会给出明确提示：

- 「仅麦克风可用：系统声通道未能启动，将听不到面试官的声音。请检查系统输出设备后在设置页重新选择并重启会话」
- 「仅系统声可用：麦克风通道未能启动，你的回答不会被识别。请检查麦克风设备与隐私权限后在设置页重新选择并重启会话」

处理：检查设备是否被其他程序独占、Windows 隐私设置是否允许麦克风访问，必要时结束面试、在「设备」卡片重新选择并重启会话。若两路都失败，开始面试会直接报「麦克风与系统声通道均无法启动…」。

**按热键没反应 / 提示热键注册失败。**

若启动时提示「全局热键注册失败：…」，说明有其它程序（截图工具、录屏、输入法、游戏辅助等）占用了同一组合键。关闭或修改冲突程序后重启 hint。热键是全局的，即使主窗口在后台也生效。

**日志在哪里？**

`%APPDATA%\com.ojbkxc.hint\logs\hint.log`（轮转文件 `hint.1.log`）。设置页底部「保存」卡片里有「打开日志目录」按钮；若目录尚未创建会提示「日志目录尚未创建：…」。

**界面打不开 / 不知道哪里配错了，怎么一次性检查环境？**

在命令行里跑 `hint.exe --doctor`（在安装目录，通常是 `%LOCALAPPDATA%\hint\hint.exe`）：

```
"%LOCALAPPDATA%\hint\hint.exe" --doctor
```

它会**不启动界面**地把环境事实收集成一份报告：版本、数据目录、语音模型是否就绪（含是否需要重新下载）、当前协议与 Key 是否已保存、Base URL 与模型名是否已填、**配置文件是否损坏**（损坏时写明已备份为 `settings.json.bad` 并标 `[阻塞]`）、会话数据库的结构版本与完整性、可用的麦克风与系统输出设备数量、最近日志里的 WARN/ERROR。有阻塞项时每项标 `[阻塞]`，末尾给出结论。

报告同时写入 `%APPDATA%\com.ojbkxc.hint\doctor-report.txt`——反馈问题时把这份报告和 `hint.log` 一起附上即可。整个过程只读：不下载模型、不改配置、不写会话。

> **关于命令行显示**：程序是 Windows GUI 子系统，启动时没有自带控制台。`--doctor` 会尝试附加到调用方的控制台并重绑 stdout——在 **cmd** / Git Bash 里能直接看到输出；**PowerShell** 因为不等待 GUI 进程、且对这类进程的管道捕获行为不同，通常看不到输出（这不是故障）。**PowerShell 下请直接看报告文件**：
>
> ```powershell
> Get-Content "$env:APPDATA\com.ojbkxc.hint\doctor-report.txt"
> ```

**如何彻底退出？**

关闭主窗口只是隐藏到系统托盘，不会退出程序。最可靠的判断方式是**把鼠标悬停在托盘图标上**：tooltip 显示「hint · 空闲（右键可退出；Ctrl+Shift+H 显示浮层）」表示没有面试在进行；显示「hint · 面试进行中（右键可结束或退出）」表示会话仍在跑。若浮层当时是打开的，还会同时看到提示「窗口已隐藏到系统托盘；右键托盘图标可退出，按 Ctrl+Shift+H 显示浮层（左键托盘图标可恢复主窗口）。」。要彻底退出，右键托盘图标，选择「退出」。托盘菜单还提供「打开设置」「显示 / 隐藏浮层」「开始面试」「结束面试」。

**截图问答可以用吗？**

可以。按 `Ctrl+Shift+S` 弹出全屏选区，拖动框住要问的区域，松开鼠标即截图并发给当前模型作答，答案在浮层的「截图问答」区块里流式出现。注意两个前提：一是当前模型必须支持视觉输入（纯文本模型会直接报错，去「模型接口」卡片换多模态模型即可）；二是选区不要超过 4096×4096，框得太大时按提示缩小重框。截图只在内存里编码后发往你自己配置的接口，不落盘、不进会话库。

**连续问了很多问题，后面的没回答。**

待答队列上限是 5 个。超出时会忽略最新一条，并提示用 `Ctrl+Shift+A` 优先作答当前问题。放慢节奏或按一次 `Ctrl+Shift+A` 即可恢复。

## 已知取舍与限制

- **截图问答需要视觉模型**：截图走当前配置的模型接口，模型不支持图片时接口会报错（不是程序故障），换个多模态模型即可；单次选区上限 4096×4096 像素，超出会提示缩小。
- **CSP 已启用（最小集）**：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src ipc: http://ipc.localhost`。`'unsafe-inline'` 仅用于 style（电平条宽度、进度百分比、浮层不透明度是运行时内联样式），脚本仍锁死 `self`；只加载本地打包资源，文本经 React 转义。
- **无自动更新**：需要手动下载新版本安装包覆盖安装。
- **仅 Windows**：仅支持 Windows 10/11 x64，NSIS 安装包；macOS 的音频采集与权限模型差异过大，不在计划内。
- **模型不随包分发**：语音模型约 241 MB，首次使用时按需下载，下载源为 huggingface.co / hf-mirror.com。模型存放在 `%LOCALAPPDATA%\hint-models`（不在应用数据目录内），**卸载程序不会删除它**——升级、卸载重装都不需要重新下载 241 MB。从旧版本升级时会自动把已下载的模型搬过去，无需任何操作。
- **问题判定是启发式**：强疑问词与句首请求动词会触发自动回答，普通陈述句不会（例如「这个方案可以落地」「我给大家介绍一下」不会触发）；纯符号 / 纯标点（STT 在静音段的幻觉）与含「哪怕 / 无论如何 / 不管怎么 / 多少有点」的陈述句也不算问题。可能漏判或误判；手动模式或 `Ctrl+Shift+A` 可兜底。
- **联合语音状态基于电平**：用 RMS 迟滞边判断「面试官在说 / 你在说 / 双方同时」，重叠说话时显示「双方同时」；极端噪声环境下可能误判。
- **断线补录有窗口**：补录只覆盖每路最近 120 秒音频，更早的片段无法补回；补录只补转录文字（行尾标「补录」），不会重新触发生成答案。
- **队列与历史上限**：待答队列 5 个；浮层答案时间线保留最近 10 轮；转录面板最近 6 行。
- **资料长度上限**：简历与项目资料各 6000 字，超出部分截断，并在提示词里标注「（内容过长已截断）」。
- **资料导入格式**：支持 TXT / MD / DOCX / PDF 文本层；旧版 `.doc` 需另存为 `.docx` / `.txt`；扫描版 PDF 不含文本层，需要外部 OCR。
- **单次流式超时 60 秒**：超时按「生成中断」处理，已输出内容保留。
- **个人知识库尚未支持**：当前版本只支持「简历 + 项目资料」全文注入；下一版规划本地个人知识库（导入 `.md` / `.txt`，分块 + 关键词检索注入，不引入嵌入模型）。

### 语音识别自检（`scripts/verify-stt.ps1`）

验证「TTS 合成语音 → voice worker → 识别结果」这条链路是否正常，也用来确认改动没破坏识别：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-stt.ps1
```

它会合成三句中文（含中英混说）喂给 worker，比对识别结果并给出 PASS/FAIL。
`-DumpDir <目录>` 可保留合成音频便于人工试听。

**这个脚本存在的理由（踩过的坑）**：

中文文本**不能**通过 stdin 传给 PowerShell。同一个字符串：

| 传法 | 合成出的音频 | 识别结果 |
|---|---|---|
| 内嵌在命令里 | 正确 | 「大家好，我是候选人。」 |
| 从 stdin 传 | **完全不同**（与正确音频相关系数 -0.0000） | 一串乱码 |

原因是 UTF-8 字节被按 GBK 解释。这个假象曾让人误判「产品中文识别坏了」，
在模型、VAD、重采样、噪声门、音效、采样率上白查十几轮——实际全是脚本自己的锅。
脚本把中文写死在代码里，就是为了不再重犯。

另外两个脚本内已处理的细节：

- **WAV 头必须是规范 44 字节**：`System.Speech` 写出的头带额外 chunk，
  worker 会拒收（`audio is not a canonical 44-byte-header WAV file`），
  脚本里做了规范化。
- **worker 的生命周期绑定 stdin EOF**：启动时 stdin 必须保持打开，
  否则它启动后立刻退出，客户端看到的是「connection reset」。

合成音频通过**不代表**真实采集通过：真实麦克风 / WASAPI loopback 是另一条路径，
那要用 `HINT_DUMP_STT` 抓真实音频再分析。

## 隐私

- 简历、项目资料、会话记录只存在本机。
- API Key 存在 Windows 凭据管理器，不写配置文件，也不进日志。
- 原始音频不落盘：采集 → 分段 → WAV 内存 → sidecar 推理，全程无文件写入。
- 截图不落盘：`Ctrl+Shift+S` 框选的那一张图只在内存里编码后随请求发给你自己配置的模型接口，不写文件、不进会话数据库、日志里不含图像数据；不做后台持续截屏与全屏轮询，只在按下热键并框选后抓取一次。
- 下载日志只记录经过脱敏的 URL（去掉 query 与临时签名）。
- 除了你自己配置的模型接口，不向任何第三方发送数据。

## 屏幕捕获排除（默认关闭）

设置页「回答行为 → 浮层外观 → 屏幕共享时隐藏浮层」，底层是 Windows 官方的
`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`。

**它默认关闭，因为实测弊大于利。** 同一台机器上按三条捕获路径实测同一个窗口：

| 对方软件的抓屏方式 | 开启后的实际效果 |
|---|---|
| GDI（`BitBlt` / `CopyFromScreen`） | 窗口区域透出下层桌面 —— 达到预期 |
| `PrintWindow` + `PW_RENDERFULLCONTENT` | **纯黑块**（R=0 G=0 B=0）—— 反而更显眼 |
| 旧式 `PrintWindow`（flag=0） | **完全绕过，内容原样可见** |

也就是说：部分会议软件（含腾讯会议某些版本）共享屏幕时，你会看到一块**黑框**——
那比被看到内容更尴尬，等于宣布「我在用工具」；而另一些抓屏方式根本拦不住。

**更可靠的做法**：面试开始前按 `Ctrl+Shift+H` 直接隐藏浮层。想用捕获排除，请先在
本地开一次屏幕共享自测，确认不会变成黑框再进会议。

## 边界

- 不做进程伪装，不注入或 hook 会议软件，不规避对方的检测机制。捕获排除是 Windows
  公开 API 的既定行为，不是对抗手段，且如上所述并不可靠。
- 只支持 Windows。macOS 的音频采集与权限模型差异过大，不在计划内。
