# hint 1.0.8 真机验收清单

- 适用产物：`hint_1.0.8_x64-setup.exe`（NSIS），或免安装的 `hint.exe`。
- 适用系统：Windows 10 / Windows 11 x64。
- 验收人：无需开发背景，按步骤操作，记录「实际结果」与「是否通过」。
- 统一日志位置：`%APPDATA%\com.ojbkxc.hint\logs\hint.log`（超过 5 MB 轮转为 `hint.1.log`）。
- 统一数据位置：`%APPDATA%\com.ojbkxc.hint\`，包含 `settings.json`、`hint.db`、`logs\`、`voice\sensevoice\`。
- 在 PowerShell 中查看日志尾部：

```powershell
Get-Content "$env:APPDATA\com.ojbkxc.hint\logs\hint.log" -Tail 100
```

- 直接打开数据目录：

```powershell
explorer "$env:APPDATA\com.ojbkxc.hint"
```

> 说明：以下「预期结果」均以 1.0.8 的实际行为为准。凡涉及具体文案的，看到意思相同的中文提示即可，不要求逐字一致。

## 一、安装

### 1.1 安装包可运行

- 步骤：双击 `hint_1.0.8_x64-setup.exe`，按向导完成安装，桌面/开始菜单出现 hint 快捷方式。
- 预期结果：安装过程不需要管理员权限（当前用户安装）；安装完成后能启动，主窗口标题为「hint · 面试提词器」。
- 失败排查：确认系统为 x64；查看安装器窗口的错误提示；`Get-ChildItem "$env:LOCALAPPDATA\Programs"` 检查安装目录（NSIS currentUser 默认位置）。

### 1.2 首次启动与数据目录

- 步骤：第一次启动后，打开 `%APPDATA%\com.ojbkxc.hint`。
- 预期结果：目录被创建，包含 `logs\hint.log`；`hint.log` 里有「日志已写入文件」一行，路径指向该目录。
- 失败排查：若目录不存在，确认程序确实以当前用户启动；检查杀毒软件是否拦截写入。

### 1.3 单实例

- 步骤：程序已运行时，再次双击快捷方式。
- 预期结果：不会出现第二个进程，已有主窗口被显示并置前。
- 失败排查：任务管理器确认只有一个 `hint.exe`；`Get-Process hint | Select-Object Id,StartTime`。

### 1.4 关闭窗口不退出

- 步骤：点主窗口右上角 ×，然后把鼠标悬停在托盘图标上。
- 预期结果：主窗口隐藏；托盘图标仍在；tooltip 显示「hint · 空闲（右键可退出；Ctrl+Shift+H 显示浮层）」。
- 浮层当时若开着：浮层顶部会出现 toast 提示「窗口已隐藏到系统托盘；右键托盘图标可退出，按 Ctrl+Shift+H 显示浮层（左键托盘图标可恢复主窗口）。」（每次启动只提示一次）。
- 失败排查：查看托盘是否有 hint 图标；任务管理器确认进程还在。

## 二、模型

### 2.1 首次下载

- 步骤：设置页「语音模型」卡片点「下载模型」。
- 预期结果：显示步骤（下载模型 / 校验文件 / 下载 VAD）、已完成字节 / 总字节（总计 241,357,257 字节，约 241 MB）、百分比与来源（官方源/镜像源）；完成后显示「已就绪」和模型目录路径。
- 失败排查：查看日志中下载相关记录；确认网络可访问 huggingface.co 或 hf-mirror.com。

### 2.2 续传

- 步骤：下载进行到约 30% 时断网 10 秒，再恢复网络，重新点「下载模型」。
- 预期结果：卡片显示「已有 X MB，支持断点续传」，下载从未完成部分继续，不从头开始。
- 失败排查：检查 `%APPDATA%\com.ojbkxc.hint\voice\sensevoice\downloads\*.part` 是否保留；日志里是否有「网络连接中断。已下载部分会保留，恢复网络后继续。」

### 2.3 校验与删除

- 步骤：已就绪状态下点「检查模型文件」；再点「删除模型」并确认。
- 预期结果：检查只核对文件是否存在与大小，不重新下载；删除后状态回到未下载，并提示需要重新下载约 241MB。
- 失败排查：若会话进行中，删除会被拒绝并提示「会话进行中，结束后再删除模型。」；先结束面试再删。

### 2.4 未下载时开始面试

- 步骤：删除模型后点「开始面试」。
- 预期结果：不进入会话，提示「本地语音模型尚未下载（约 240MB），请先在设置页下载模型后再开始会话。」
- 失败排查：确认模型卡片状态不是「已就绪」。

### 2.5 磁盘不足

- 步骤：在可用空间小于约 300 MB 的磁盘/分区上执行首次下载。
- 预期结果：开始前即提示「磁盘空间不足：当前可用约 X MB，本次还需要约 Y MB」。
- 失败排查：`Get-PSDrive` 查看剩余空间；清理空间后重试。

## 三、双通道

### 3.1 双路电平

- 步骤：开始面试，显示浮层（`Ctrl+Shift+H`）。对麦克风说话，同时播放一段音频。
- 预期结果：浮层底部「麦克风」「系统声」两条电平条分别随对应声音跳动；转录区分别出现「我」与「面试官」行。
- 失败排查：检查设置页「设备」卡片选择的设备是否正确；确认系统输出正在播放声音。

### 3.2 通道缺失提示

- 步骤：在系统声音设置里禁用麦克风（或拔掉麦克风），开始面试。
- 预期结果：会话仍启动但明确提示「仅系统声可用：麦克风通道未能启动，你的回答不会被识别。请检查麦克风设备与隐私权限后在设置页重新选择并重启会话」。
- 失败排查：检查 Windows 设置 → 隐私 → 麦克风是否允许桌面应用访问；检查设备是否被其它程序独占。

### 3.3 两路都不可用

- 步骤：同时禁用麦克风与系统输出设备后开始面试。
- 预期结果：启动失败，提示「音频采集启动失败…」或「麦克风与系统声通道均无法启动，请检查系统音频设备与麦克风隐私权限」。
- 失败排查：恢复设备后重试；查看日志中的音频初始化错误。

### 3.4 回声过滤

- 步骤：不戴耳机、外放一段面试官提问音频，同时让麦克风能拾取到扬声器声音。
- 预期结果：转录区麦克风通道的重复内容被标为「回声」（行尾有「回声」标记），不重复触发生成。
- 失败排查：建议改为佩戴耳机；回声判定为启发式，短句（少于 6 个汉字或少于 12 个英文字母）不判回声。

### 3.5 联合语音状态

- 步骤：开始面试并显示浮层。先只播放面试官音频，再只对麦克风说话，最后同时进行。
- 预期结果：电平条旁依次出现「面试官在说」「你在说」「双方同时」标识；停顿时标识消失；来回切换不闪烁。
- 失败排查：确认电平条本身有跳动（无电平先查设备）；查看日志是否有连续「语音识别停滞」。

## 四、STT

### 4.1 中文识别

- 步骤：清晰说一句面试问题，例如「请介绍一下你最近做的项目」。
- 预期结果：约 1 秒内转录区出现文字；自动模式下随后开始生成答案。
- 失败排查：确认电平条有跳动；查看日志「本地语音识别失败」相关行。

### 4.2 识别失败自动重试

- 步骤：在面试进行中手动结束语音 worker 进程（任务管理器结束 `hint.exe` 的 `--voice-worker` 子进程）。
- 预期结果：会话不结束，浮层提示「语音识别失败，稍后自动重试：…」；下一页语音到来时 worker 自动冷启，识别恢复（冷启可能慢几秒）。
- 失败排查：查看日志 worker 启动/退出记录；必要时结束并重新开始面试。

### 4.3 模型损坏

- 步骤：结束面试，手动改坏 `%APPDATA%\com.ojbkxc.hint\voice\sensevoice\models\model.int8.onnx`（例如用记事本截断），再开始面试。
- 预期结果：提示「本地语音模型加载失败，模型文件可能已损坏，请在设置页删除模型后重新下载（…）」；按提示删除并重新下载后恢复。
- 失败排查：确认删除的是整个模型（卡片「删除模型」），而不是只删单个文件。

### 4.4 语言参数

- 步骤：播放英文提问，例如「Can you walk me through your project?」
- 预期结果：英文被正常识别并转录；回答语言跟随提问语言（英文提问用英文作答）。
- 失败排查：确认播放音量足够；识别语言参数固定为 `auto`。

### 4.5 识别卡住自动回收

- 步骤：面试进行中，用调试器或挂起方式让 `--voice-worker` 子进程停止响应。
- 预期结果：约 15–30 秒内日志出现「语音识别停滞，中止当前推理并回收 worker 触发冷启」，随后识别自动恢复；期间会话不结束。
- 失败排查：确认版本含 abort 轮询逻辑；查看日志 worker 启动/退出记录。

### 4.6 断线补录

- 步骤：按 4.2 结束 worker 进程，随即继续说 10–20 秒；等识别恢复并静置几秒。
- 预期结果：恢复后转录区补出中断期间的句子，行尾标「补录」；与实时识别内容不重复；补录的面试官问题只补转录、不重复触发生成。
- 失败排查：查看日志「断线补录完成」计数；补录依赖每路 120 秒环形缓冲，超过窗口的音频无法补回。

## 五、LLM 三协议

每个协议都先做「测试连接」，再在会话中验证流式输出。

### 5.1 OpenAI 兼容

- 步骤：选择「OpenAI 兼容」预设（如 DeepSeek），填写有效 Base URL（到 `/v1` 一级）、模型名与 Key，点「测试连接」；开始面试提问。
- 预期结果：测试连接返回一段回答与模型名；会话中答案逐字流式出现，底部显示首字延迟。
- 失败排查：404 时核对 Base URL 与模型名；401 时重新保存 Key。

### 5.2 Anthropic Messages

- 步骤：选择 Claude 预设，Base URL 填 `https://api.anthropic.com`（带 `/v1` 也可），填写有效 Key，测试并提问。
- 预期结果：连接成功；流式答案正常；Base URL 带不带 `/v1` 都不会出现 `/v1/v1/messages`。
- 失败排查：日志中查看请求 URL；尝试去掉或加上 `/v1` 对比。

### 5.3 Gemini

- 步骤：选择 Gemini 预设，Base URL 填 `https://generativelanguage.googleapis.com`（带 `/v1beta` 也可），模型填 `gemini-2.5-flash`。
- 预期结果：连接成功；流式答案只包含可见回答，不包含思维链（thought）；若使用返回整包 JSON 的兼容代理，也能正常出答案。
- 失败排查：日志查看 `streamGenerateContent` 请求；确认模型名没有重复 `models/` 前缀。

### 5.4 重新生成

- 步骤：对同一问题按 `Ctrl+Shift+A`（或点浮层「重新生成」）。
- 预期结果：当前生成被取消，重新请求；答案区出现新一轮答案，旧答案进入下方时间线。
- 失败排查：确认会话仍在「面试进行中」；日志查看 regenerate 记录。

## 六、会话与导出

### 6.1 开始 / 结束

- 步骤：设置页点「开始面试」，观察状态；结束后切到「会话复盘」。
- 预期结果：状态依次为「正在启动…」（加载模型 10–30 秒）→「面试进行中」；结束后「会话复盘」出现本次会话，显示开始/结束时间、模型、转录与答案数量。
- 失败排查：若状态停在「启动失败」，按提示检查 API Key 与语音模型；日志查看 start_session 错误。

### 6.1.1 浮层随面试自动开关

- 步骤：先按 `Ctrl+Shift+H` 把浮层收起，再点「开始面试」；面试进行中按 `Ctrl+Shift+H` 收起浮层，然后点「结束面试」。
- 预期结果：开始面试时，若浮层处于隐藏状态会自动弹出（开始即能看到转录与两路电平）；结束面试后浮层自动收起。空闲状态下用 `Ctrl+Shift+H` 手动开关浮层不受影响。
- 失败排查：确认没有在结束前手动显示浮层又被其它操作干扰；日志查看 session started / stopped 与窗口 show/hide 记录。

### 6.2 Markdown 导出

- 步骤：在「会话复盘」选中会话，点「导出 Markdown」。
- 预期结果：浏览器式下载生成 `<会话编号>.md`；内容包含开始/结束时间、协议/模型、逐段转录（回声标「回声，已排除」）与每个问题的全部答案（含多次重新生成）。
- 失败排查：确认已选中会话；导出内容为空时会提示「导出失败：后端返回内容为空」。

### 6.3 连续多问

- 步骤：5 秒内连续说两个问题（或先后播放两段提问音频）。
- 预期结果：两条都有答案，顺序与提问一致；第二个答案在第一个完成后出现；首个问题作答时「排队 N」为 1，第二题开始作答时徽标消失（0）。第二题入队瞬间应看到排队数实时变化，不需要等第一题答完。
- 失败排查：确认第一段问题结束后才开始第二段；查看日志 queue 相关 debug 行。

### 6.4 流式过程中提出第二个问题

- 步骤：第一个答案仍在流式输出时，立即提出第二个问题。
- 预期结果：第一个答案不被清空或取消，继续输出到结束；第二个问题进入队列，浮层「排队 N」立即从 0 变为 1，第一个答案完成后自动开始第二轮，此时「当前问题」切换为第二问、排队数递减。
- 失败排查：确认不是按了 `Ctrl+Shift+A`（那是唯一会打断的行为）。

### 6.5 重复识别去重

- 步骤：对同一句话让 STT 重复识别（例如连续两次播放同一段提问音频）。
- 预期结果：只生成一个答案，不产生两个；日志有「重复问题，跳过入队」。去重只忽略标点、空白与礼貌用语（「请」「麻烦」「呢」「吗」等）的差异，例如「请介绍一下你自己？」与「介绍一下你自己」视为同一句。
- 失败排查：确认两段音频内容确实相同（内容有差异时不应去重）。

### 6.5.1 追问不被合并

- 步骤：先提问「介绍一下你的项目」，紧接着追问「介绍一下你的项目难点」。
- 预期结果：两个问题都进入队列并分别作答，第二条不会被当成重复静默丢弃。
- 失败排查：若第二条没有答案，查看日志是否有「重复问题，跳过入队」；确认使用的是 1.0.1 产物（旧版按「短句被长句包含且长度≥80%」判重，会误吞这类追问）。

### 6.6 队列上限

- 步骤：连续提出超过 5 个待答问题（在答案生成较慢的模型下容易复现）。
- 预期结果：待答满 5 个后，最新一条被忽略，提示「问题积压较多，已忽略最新一条；可按 Ctrl+Shift+A 优先作答当前问题」；按 `Ctrl+Shift+A` 后优先回答最新问题。
- 失败排查：确认提示是否被浮层 toast 遮挡；查看日志队列上限记录。

### 6.7 连续时间线

- 步骤：连续完成 3 个问题后，在浮层答案区上下滚动。
- 预期结果：最新一轮问答完整显示在最上方；之前两轮按时间倒序依次排在下方；无重复、无丢失；浮层缩小到 320×180 时仍可通过滚动查看全部内容。
- 失败排查：确认没有切换新会话（切换会清空历史）；历史上限为最近 10 轮。

### 6.8 浮层最小尺寸适配

- 步骤：把浮层拖到最小尺寸（320×180），让答案区有内容（占位提示或一段真实答案），再观察是否出现横向滚动条。
- 预期结果：答案区至少能显示 3 行内容，不出现横向滚动；极矮窗口下转录区自动隐藏（`@media (max-height: 200px)`），把空间让给答案；问题行与工具栏仍在，不重叠。底部电平条与「当前模型 / 首字延迟」不被裁切；窄到 320px 时「麦克风 / 系统声」文字标签自动隐藏，只保留电平条（悬停仍有提示）。
- 补充：把浮层拉回 460×340，转录区恢复显示（上限约 42% 高度），答案区不再被压缩。
- 失败排查：确认窗口确实到达最小尺寸（`tauri.conf.json` 中浮层 minWidth 320 / minHeight 180）；若答案仍被裁切，检查 `src/App.css` 末尾的 `@media (max-height: 240px)` 与 `@media (max-height: 200px)` 是否被同优先级基础规则覆盖。

### 6.9 主窗口窄宽适配

- 步骤：把主窗口拖窄到 860px 以下（最小宽度 760px）。
- 预期结果：设置页所有卡片单列堆叠，不发生跨列（首张卡片与保存卡片不再占满两列）；「会话复盘」页的「历史会话」与「转录与问答」上下排列，而不是左右分栏。
- 补充：把窗口拉回 860px 以上，设置页恢复两列，复盘页恢复左右分栏。
- 失败排查：确认窗口宽度确实小于 860px（`tauri.conf.json` 主窗口 minWidth 760）；若仍双列，检查 `src/App.css` 末尾的 `@media (max-width: 860px)` 是否在 `.dashboard-grid` / `.review-layout` 基础规则之后。

### 6.10 会话记录清理

- 预期结果：全部记录被删除；会话进行中点清空会提示「会话进行中，结束后再清空会话记录。」
- 失败排查：确认两次确认框都点了「确定」。

- 预期结果：点「保存全部配置」后不重启，**整个浮层**（包括转录区、答案区、头尾栏）都明显变透，能清楚看到下方的画面；答案文字是深色字 + 白色光晕，仍然清晰可读。
- 步骤：把滑块分别调到 50% 与 100%。
- 预期结果：50% 时整体半透（白色 50%），画面隐约可见但比 20% 更实；100% 时纯白不透明，看不到背后画面。两档下文字可读性不变。
- 步骤：退出程序，把 `%APPDATA%\com.ojbkxc.hint\settings.json` 里的 `"overlayOpacity"` 手动改成 `0` 或 `5`，保存后重启。
- 预期结果：浮层不会消失，文字也不会不可读——后端保存时与前端读取时都夹取到 0.2–1.0；改 `0` 按 20%（最透、文字仍清晰），改 `5` 按 100%（完全不透明）。手改文件只在重启后生效。
- 失败排查：确认改的是 `settings.json`（不是 `settings.json.bad`）、字段名为 camelCase 的 `overlayOpacity`；保存后日志无「保存配置失败」；若完全透不出画面，先确认系统「透明效果」已开启（设置 → 个性化 → 颜色 → 透明效果），再检查 `src/App.css` 中 `.overlay-root` 的背景是否为 `rgba(255,255,255, var(--overlay-alpha))`。

- 失败排查：`Get-Process hint` 确认无残留；查看日志 shutdown 记录。

## 八、资料导入与接口智能

### 8.1 TXT / MD 导入（UTF-8 / UTF-16 / GBK）

- 步骤：准备一个 UTF-8 编码的 `.txt` 简历（不少于 500 字）、一个 GBK 编码的 `.txt`（Windows 记事本「另存为」选 ANSI），以及一个记事本「Unicode」保存的 UTF-16LE `.txt`，分别在「资料注入」卡片的「简历」右上角点「从文件导入」。
- 预期结果：文件选择框只显示 TXT / MD / DOCX / PDF；选中后文本填入对应输入框，状态行显示「已导入 xxx（N 字）」；GBK 与 UTF-16 文件的中文都不乱码、不出现 `\0` 方块。
- 失败排查：确认文件不是空文件；超过 20 MB 会被拒绝并提示上限；超过 6000 字会截断并提示原文长度。

### 8.2 DOCX 导入

- 步骤：用 Word 保存一份带多个段落的 `.docx` 简历，导入到「简历」；再导入到「项目资料」。
- 预期结果：段落结构保留（每个 Word 段落一行），中文、英文与 `&` 等符号正常；状态行显示字数。
- 失败排查：确认不是旧版 `.doc`（会提示另存为 `.docx`）；确认文件没有加密/损坏。

### 8.3 PDF 导入

- 步骤：准备一份带文本层的 PDF（例如 Word 另存为 PDF），导入到「简历」。
- 预期结果：文本被提取并填入；文字顺序基本正确（复杂排版可能有多余空行，属正常）。
- 步骤：再导入一份扫描版 PDF（整页是图片）。
- 预期结果：提示「没有从文件里提取到文字（扫描版 PDF 需要先用 OCR 转成文本）」或其他等价中文提示，不会崩溃。
- 失败排查：扫描版 PDF 需要外部 OCR，本版不支持；如提示「解析 PDF 失败」，换一份 PDF 或另存为 DOCX。

### 8.4 不支持格式与异常文件

- 步骤：尝试导入 `.doc`、`.png`、无扩展名文件、空文件。
- 预期结果：分别提示「不支持旧版 .doc：请…另存为…」「不支持的文件类型 .png…」「无法识别文件类型（没有扩展名）…」「文件是空的」；输入框内容不变。

### 8.5 Base URL 自动补全

- 步骤：在 Base URL 输入框依次填写 `api.deepseek.com`、`https://api.deepseek.com`、`https://api.deepseek.com/v1/chat/completions`，每次按 Tab 或点空白处让输入框失焦。
- 预期结果：失焦后分别显示 `https://api.deepseek.com/v1`、`https://api.deepseek.com/v1`、`https://api.deepseek.com/v1`（完整端点被剥掉，裸域名补上 `/v1`）。
- 失败排查：确认是 OpenAI 兼容协议；Anthropic / Gemini 不会补 `/v1`（由后端各自拼接）。

### 8.6 协议自动识别

- 步骤：先把协议切到「OpenAI 兼容」，在 Base URL 填 `https://api.anthropic.com`；再填 `https://generativelanguage.googleapis.com`；再填 `https://api.deepseek.com`。
- 预期结果：失焦后协议分别自动切换为「Anthropic Messages」「Gemini generateContent」「OpenAI 兼容」；自建网关域名（如 `https://my-gateway.example.com`）保持当前协议不变。

### 8.7 测试连接使用未保存的 Key

- 步骤：切换到某个还没保存过 Key 的协议（例如从未用过的 Gemini），把有效 Key 粘贴进输入框，**不点「保存」**，直接点「测试连接」。
- 预期结果：不再出现「读取 API Key 失败：…No matching credential found」；连接成功后状态显示「连接成功，模型：…；API Key 已保存」，Key 输入框清空，下次启动可以直接用。
- 步骤：清空 Key 输入框（且该协议没有已保存的 Key）再点「测试连接」。
- 预期结果：提示「当前接口还没有保存 API Key：请在上方输入框粘贴 Key 后点「保存」，或直接点「测试连接」自动保存并测试」，不暴露凭据管理器内部错误。

## 九、异常场景

### 9.1 Base URL 错误（协议与地址不匹配）

- 步骤：选择「OpenAI 兼容」，Base URL 填 `https://api.anthropic.com/v1`，模型名随便填，保存后开始面试并提问。
- 预期结果：浮层答案区出现红色错误条，中文说明「接口地址或模型名不存在。请检查 Base URL 与模型名（当前：… / …）」并附原始响应片段；错误条**没有**「重试」按钮；会话仍在「面试进行中」，「结束面试」仍可点。
- 失败排查：`Get-Content "$env:APPDATA\com.ojbkxc.hint\logs\hint.log" -Tail 50` 查看 HTTP 状态码。

### 9.2 Base URL 不可达

- 步骤：Base URL 改为 `https://invalid.example.com`，保存后开始面试并提问。
- 预期结果：先出现「稍微慢一点」（后端在首字前自动重试一次，间隔约 1.5 秒）；仍失败后出现错误条，中文提示无法连接或超时；错误条**有**「重试」按钮；点「重试」再次尝试，仍失败则再次报错；会话不结束。
- 失败排查：确认本机网络/DNS；`Resolve-DnsName invalid.example.com` 应解析失败。

### 9.3 API Key 错误

- 步骤：使用有效 Base URL 与模型，故意粘贴一个错误 Key，保存后提问。
- 预期结果：错误条中文提示「API Key 无效或已过期。请到设置页重新保存 Key（当前协议：…）」；**没有**「重试」按钮（重试无用）；会话仍在「面试进行中」。
- 修复：设置页重新粘贴正确 Key 点「保存」，再按 `Ctrl+Shift+A` 重新生成。

### 9.4 网络中断后恢复

- 步骤：面试进行中，用「禁用网络适配器」或拔网线断网 5 秒后恢复（提问已在生成中）。
- 预期结果：若已输出部分内容，错误条提示「生成中断（已保留已生成内容，…）」，已生成文字不丢失；恢复网络后点「重试」或按 `Ctrl+Shift+A` 可重新得到答案；会话状态不变。
- 失败排查：日志查看「生成中断」与重试记录；确认网络确实已恢复。

### 9.5 切换默认播放设备

- 步骤：面试进行中（设置页输出设备选择「系统默认」），在 Windows 声音设置里切换默认播放设备。
- 预期结果：浮层只出现一条「警告：系统默认输出设备已变更，正在切换到新的输出设备继续采集」（属正常路径，不计入通道失败、不弹「采集中断」）；采集自动迁移到新设备，恢复后「系统声」电平条继续跳动。
- 连续插拔耳机 / 蓝牙反复闪断 5 次以上：系统声通道仍应存活（此前每次切换都算一次失败，15 秒超限后通道被判死，症状是「系统声电平条不再跳动」）。
- 若设置页显式指定了某个输出设备：浮层状态栏出现「警告：系统默认输出设备已变更，当前会话仍在采集旧设备，可能听不到面试官；请结束会话，在设置中重新选择输出设备并重新开始」（只提示一次）。
- 失败排查：确认不是「静默无声」；按提示结束会话、重新选择设备并开始；日志搜索「系统默认输出设备已变更」。

### 9.6 蓝牙耳机短暂断开

- 步骤：面试进行中让蓝牙耳机断开约 5 秒再重连。
- 预期结果：不立即判定致命；通道自动重连（宽限 15 秒）。超过 15 秒仍失败才会提示「麦克风 / 系统声通道连续 5 次失败，采集引擎停止」，状态栏转为「连接异常」并结束会话。
- 失败排查：查看日志音频重连记录；必要时重新选择设备。

### 9.7 关闭主窗口

- 步骤：面试进行中点主窗口 ×，再悬停托盘图标。
- 预期结果：主窗口隐藏到托盘；托盘 tooltip 显示「hint · 面试进行中（右键可结束或退出）」，据此可确认会话仍在运行；浮层当时若开着会同时出现「窗口已隐藏到系统托盘…」提示（每次启动只提示一次）；会话不受影响，托盘可正常结束或退出。
- 失败排查：左键托盘图标恢复主窗口；任务管理器确认进程仍在。

### 9.8 限流与服务端异常

- 步骤：使用会返回 429 或 5xx 的接口（或短时间高频触发）。
- 预期结果：错误条提示「请求过于频繁或超出限额。稍等片刻后点「重新生成」重试。」或「模型服务端异常。稍等片刻后点「重新生成」重试。」；有「重试」按钮；会话不结束。
- 失败排查：日志查看状态码；稍后重试。

### 9.9 配置损坏

- 步骤：退出程序，把 `%APPDATA%\com.ojbkxc.hint\settings.json` 改成非法 JSON，再启动。
- 预期结果：程序正常启动并回退默认配置；原文件被重命名为 `settings.json.bad` 留证；日志有「配置文件损坏，已备份并回退默认值」。
- 失败排查：检查数据目录是否存在 `settings.json.bad`。

### 9.10 日志与反馈

- 步骤：设置页底部点「打开日志目录」。
- 预期结果：资源管理器打开 `%APPDATA%\com.ojbkxc.hint\logs`；日志目录不存在时提示「日志目录尚未创建：…」。
- 反馈要求：附上 `hint.log`（若超过 5 MB 一并附 `hint.1.log`）、复现步骤与发生时间。
